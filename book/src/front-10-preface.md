# 序：为什么写这本书

> 这本书是我为自己写的，后来觉得对别人可能也有用，就整理成了书。
> 它的出发点只有一个：**会用 `git` 的命令，和真正理解 Git 是怎么工作的，是两件事。**

---

## 一、动机：我也曾经"会用但不懂"

和大多数人一样，我最开始学 Git 是背命令：`add`、`commit`、`push`、`pull`，
出问题就搜报错、抄解决方案。这样能干活，但总会撞上几堵墙：

- `git reset --soft` 和 `--hard` 到底差在哪？为什么有人按错了就丢工作？
- 为什么"改一下提交信息"会把后面所有提交的哈希都换掉？同事为什么被迫重新 clone？
- `.gitignore` 明明写了，为什么这个文件还在被提交？
- `git diff main` 和 `git diff main...HEAD` 为什么结果不一样？审查 PR 到底该用哪个？
- "提交丢了"——真的丢了吗？为什么 `reflog` 能捞回来？

这些问题的答案都不在命令手册里，而在 **Git 的内部模型**里：
对象是什么、引用是什么、索引是什么、diff 是怎么算出来的。

**看懂模型，命令就变成了推论。** 你不再需要背"什么时候用 `--soft`"，
因为你知道它只移动了一个指针。

---

## 二、为什么拿我自己的 sourcepack 当标本

理解原理最好的方式是**拆一个真实的东西**，而不是看玩具示例。
我手边正好有一个合适的小项目：**sourcepack**——一个把代码库打包成
Markdown 快照、方便喂给 LLM 的工具（本仓库就是它）。

选它当标本，是因为它同时满足几个条件：

| 条件 | sourcepack 的情况 |
| :--- | :--- |
| **规模适中** | 约 6400 行 Go（含测试；非测试代码约 3900 行），一个下午能通读；不是"helloworld"级别的玩具 |
| **真的在用 Git** | 写作时有 153 个提交、42 个发布 tag、经历 3 次改名——有真实的历史可挖 |
| **踩过真坑** | 二进制误判、`--staged` 计数恒零、Windows 装不上、幽灵变更……每个坑都对应一条 Git 原理 |
| **大量调用 Git** | 它的核心功能就是"读 Git"：`diff`、`log`、`ls-files`、`rev-parse` 全用上了 |
| **代码可读** | 关键决策都写了注释，包括"为什么不用 go-git"这种设计取舍 |

> 上表的数字会随项目演进（这正是"活文档"的代价）。如果你读到它时已经不准了，
> 用 `git rev-list --count HEAD` 与 `git tag | wc -l` 自己数一遍即可——
> 顺便说，这种"不轻信文档、当场自数"的习惯，正是第 1 章三条方法论的第一条。

于是这本书有个特点：**每个 Git 概念都能在本仓库的代码里找到落点**。
讲空树对象时，我们能指着 `changeset.go` 里的常量说"就是它"；
讲忽略规则时，能直接看 `ignore.go` 怎么实现；
讲发布链路时，看的就是本仓库的 `.github/workflows/release.yml`。

**Git 的原理不再抽象——它就在你正在读的这个仓库里。**

## 三、这本书怎么读

**先选一条阅读路径。** 三条完整路径（含逐节清单与时长）在 **附录 C.3**，这里给最省事的判断：

| 你的情况 | 怎么读 | 约 |
| :--- | :--- | ---: |
| 完全新手，只想"不再怕" | **速成路径**：前言 → 第 1 章 → 第 3 章 → 第 4 章 → 第 5.6–5.8 节 → 第 7.4、7.6 节 → 第 9.2、9.8 节 | 3 小时 |
| 想真正建立模型 | 第 1 章一路读到第 12 章，每章都动手做实验 | 12 小时 |
| 已有使用经验 | 直接跳到感兴趣的章；每章开头"本章目标"说明它解决什么问题 | — |
| 遇到具体问题 | 看下面的对照表，或附录 C.2 那张 47 行的"困惑 → 章节"表 | — |

> ⚠️ **"按顺序全读"并不等于"对新手友好"。** 这本书有几处**字节级深潜**——
> 对想弄清底层的人很值，但如果你还没建立起整体模型，硬啃会挫败。
> **它们都可以先跳过**，因为每节都先给结论、再拆细节，跳过不影响后面的理解。
> 小节标题带 `[深潜]` 就是提醒"可以晚点回来"：

| 可跳过的小节 `[深潜]` | 讲什么 | 跳过后不受影响的 |
| :--- | :--- | :--- |
| 2.2–2.3 | 用 Python 复现哈希、拆开 zlib 压缩后落盘的对象 | 第 3 章起的全部内容 |
| 4.2 | 逐字节读索引的 `DIRC` 二进制头 | 4.3 起对 `add` / staged 的理解 |
| 10.2–10.4 | delta 压缩、commit-graph、bitmap 的量化对比 | 10.5 起的结论与实用建议 |

全书结构（与附录 C.1 的依赖图一致）：

```
第一部  地基             第 1–2 章     快照 / 内容寻址 / 三棵树
第二部  日常操作的真相    第 3–5 章     引用与 reflog / 索引 / 提交图与合并
第三部  格式与传输        第 6–8 章     diff 与 patch / 忽略规则 / 远端
第四部  改写、性能与工程  第 9–10 章    改写与恢复 / 性能与底层

```

**如果你只是遇到了具体问题**，看看这几章的对应关系：

| 你的困惑 | 去哪一章 |
| :--- | :--- |
| 分不清 staged / unstaged / untracked | 第 4 章 |
| 不敢用 `reset`，怕丢东西 | 第 9 章（顺便学会怎么救回来） |
| 不知道该和哪个分支比较 | 第 5 章 |
| `.gitignore` 不生效 | 第 7 章 |
| 合并/变基之后同事被迫重新 clone | 第 9 章 |
| 想写一个"读 Git"的工具 | 第 12 章（有 12 条 checklist） |

**需要什么前置知识**：会用命令行、装过 Git 就够了。
**不需要会 Go**——代码片段只用来"指认现场"，每段都有中文注释与解释
（唯一的例外是第 12 章：那章要对照 `changeset.go` 读；但即便完全跳过 Go 代码，
只读该章的结论与 12.9 的 12 条 checklist，也能拿走绝大部分价值）。

**重要：实验请在隔离的克隆里做。** 第 1 章第一件事就是教你这个：

```bash
git clone <本仓库或你自己的仓库> /tmp/git-lab
cd /tmp/git-lab && git config user.email lab@example.com && git config user.name Lab
```

后面的 `reset --hard`、`rebase`、`filter-branch` 之类都在这里折腾——
**这也是我在写这本书时遵守的规矩**：每一章的实验都在 `/tmp` 下的隔离克隆里做，
本仓库只被"追加"了教程与成书文件（153 个提交、0 个合并提交，历史保持线性），
没有因为写这本书而被 reset / rebase / amend 过。

> 顺带说明：本仓库**历史上**确实有过 `rebase` 与 `pull --rebase`（2026 年
> 4 月与 8 月两次，都在写这本书之前，是我自己整理代码时留下的），`git reflog`
> 里还能看到 7 条相关记录。这正好是第 9 章讲的"改写会留下痕迹"的实例。

## 四、这本书的写法

书里每一章都是同一个骨架，长得一样，方便你把注意力放在内容而不是版式上：

1. **本章目标**——开头一段引用块，列出学完这一章你应该能回答的几个问题。
   它也是给跳读者用的：看完这段就知道该不该读下去；
2. **正文**——按 `N.1`、`N.2` 这样的编号小节推进，先讲机制、再讲操作，
   最后有一节**"回到 sourcepack"**，把刚讲的 Git 行为映射回本仓库的代码；
3. **动手实验 `[lab]`**——一章末尾一段可直接照抄的命令清单，边跑边对照；
4. **自测题**——几道需要推理、不能靠搜索直接抄到答案的问题。
   每章的自测题后面都跟着一个**折叠的「点开看答案」**（用 `<details>` 实现，默认收起，
   所以不会剧透；HTML 与 EPUB 里都能正常展开）。**建议先自己答完再点开**——
   这些题的价值在"想"的过程，答案只是用来对账的；
5. **小结**——把这一章的结论压成几条，并给出**下一章**的预告。

阅读约定有四条，贯穿全书：

- 代码块里 **`$` 开头的是命令**，紧随其后的就是它的**真实输出**（不是示意、不是删节版）；
- 标注 **`[lab]`** 的命令在隔离克隆 `/tmp/git-lab` 里执行，
  标注 **`[repo]`** 的在 sourcepack 本体执行——两者的区别是会不会改写历史；
- 凡涉及"为什么 sourcepack 这么写"的地方，都会给出 `文件:行号`，
  比如 `changeset.go` 里的空树常量。行号会随代码演进漂移，所以请**对照函数名一起看**。
- 做题遇到卡壳，**先回看那一章的小节**再展开答案；答案里都写了它依据的是哪一节
  （例如"见 4.1 那张图"），可以顺着回去补。
- 实验与输出都在 **macOS + git 2.39.5** 上跑出，因此管道命令是 Unix 风格。
  **Windows 读者请看附录 D 的「Windows 读者的实验环境」**——那里列了逐条替代做法，
  以及为什么"在 Git Bash 里做实验"几乎可以原样照抄。

## 五、三条方法论（可能比知识点更重要）

这本书有三条贯穿始终的做法，我认为它们是它区别于"命令速查"的地方：

> **速读版**：① 每个数字都当场跑出来；② 拿 Git 自己当标准答案；③ 写错就改，并留下"为什么错"。
>
> 记住这三句，下面每条的具体展开可以跳读。

### 1. 一切以实测为准 —— 每个数字都能复现

书里的每一个数字、每一段输出，都是**在本机跑出来的**，不是从记忆或文档里抄的。
你会在正文里看到很多这样的句子：

> 实测：`--depth=1` 让 pack 从 8.96MB 涨到 49.8MB（**5.6×**）。

甚至包括**我没测出差异**的地方，也照实写：

> bitmap 生成 399K 文件，但本机规模下 `rev-list`/克隆**未测出差异**——
> 它优化的是服务端 `pack-objects` 的可达性计算。

**把"没测出差异"如实写出来，比编一个好看的数字有用。**

### 2. 以 Git 自己为真值 —— 拿标准实现当答案

讲忽略规则时，我没有靠"我觉得应该是这样"，而是写了一张
**14 个模式 × 40 条路径**的表，逐条和 `git check-ignore` 对照。
第一次跑就抓到了我自己理解错的地方：

> `a/**/b` 之下，`a/b/c` 也被忽略——因为 `a/b` 这一级目录命中了规则，
> 而 git 规定"父目录被排除 → 其内容一律排除，`!` 也救不回"。

**这不是靠"想用例"能覆盖到的，是 Git 告诉我答案的。**

### 3. 写错就改，并且把"为什么错"留下 —— 错误也是教材

书里保留了若干处我自己的错误与修正，例如：

- 我原以为 `abc/**` 会匹配 `abc` 自身——实测**不匹配**；
- 我原以为空仓库（unborn HEAD）下 `symbolic-ref` 会失败——实测它**成功**；
- 我原以为合并之后 `git diff main...feature` 仍有内容——实测是**空的**。

**知道一个结论"从哪来"，比记住结论更抗遗忘。**

## 六、学完之后你能得到什么

不是"记住了 60 个命令"，而是几件更耐用的东西：

1. **一个能推理的模型**：对象库（不可变）、引用（可移动的指针）、索引（候选快照）。
   遇到没见过的命令，你能猜出它动了哪一块；
2. **敢做操作**：知道"对象不可变"之后，你会明白为什么
   `reset --hard` 丢掉的提交还能捞回来（第 3、9 章有完整演练）；
3. **能写工具**：第 12 章把"如何安全地读一个 Git 仓库"总结成 12 条 checklist，
   包括那些不写就会在 CI 里挂死的细节（禁分页器、禁交互、`-z` 解析、固定 diff 前缀……）；
4. **一套检验自己理解的方法**：以真值为准做对照测试、动手复现、
   以及"改回错误实现看测试是否变红"的反向验证。

## 七、一点诚实的说明

- **这本书不追求"全覆盖"**。它偏重"理解模型"，对某些命令族的穷举
  （比如 `git bisect`、submodule、worktree、`rerere`）着墨很少甚至没写——
  那些更适合在用的时候查文档；
- **示例里的数字与本机环境有关**（macOS、git 2.39.5、Apple Silicon）。
  性能类的结论（第 10 章）在不同机器上会变，但**机制**不变；
- **书里引用的代码行号**（如 `changeset.go:496-499`）对应写作时的版本。
  如果本仓库代码继续演进，行号会漂——建议对照函数名一起看；
- 这本书是**边做边写**的：讲到哪、测到哪、写到哪。如果发现哪里不对，
  欢迎直接改本仓库里的 `git-course/`——它和代码放在一起，就是为了方便被修正。

## 八、开始吧

如果你只想记一件事：

> **Git 不存储"变化"，它存储"状态"；而所有历史操作，本质上都是在移动指针。**

带着这句话读第 1 章，你会轻松很多。

准备好了就从 **第 1 章：起源与设计哲学** 开始。
每章末尾都有"动手实验"和"自测题"，请务必动手——
**这本书里所有让你恍然大悟的时刻，都发生在敲下回车之后。**
